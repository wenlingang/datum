# 数据库开发规范

供 AI 生成或修改 SQL 时遵循。标记含义:【必须】违反会被判定为错误答案;【禁止】不得出现;【推荐】优先采用,允许合理例外(需说明理由)。未标注方言的规则同时适用于 PostgreSQL 与 MySQL;SQLite、Redis 见各自章节。

## 0. 总则

- 【必须】按当前连接的数据库类型与版本生成 SQL,不混用方言(如在 MySQL 写 `::int`、`ILIKE`,在 PostgreSQL 写反引号、`AUTO_INCREMENT`、`LIMIT m, n`)。
- 【必须】只依据已知表结构写 SQL;表名、列名、类型不确定时先查元数据(`information_schema`、MySQL `SHOW CREATE TABLE`、SQLite `PRAGMA table_info`),不臆造字段。
- 【必须】应用代码中的 SQL 用参数占位符(`$1` / `?`)传值,【禁止】把用户输入拼接进 SQL。
- 【必须】涉及数据修改、结构变更或删除时,明确指出影响与风险,并给出验证或回滚方式。
- 【推荐】关键字大写、标识符小写,复杂语句换行缩进;只读需求只给只读语句。

## 1. 命名

- 【必须】库、表、列、索引名只用小写字母、数字、下划线(snake_case)且以字母开头;【禁止】大写、数字开头、空格、连字符、中文。
- 【禁止】用保留字作标识符(如 `user`、`order`、`group`、`desc`、`key`、`range`、`match`、`rank`);沿用旧名时必须加引号。
- 【禁止】依赖带引号的大小写敏感标识符(PG 中 `"UserName"` 与 `username` 是两个名字)。
- 【推荐】表名用"业务域_实体"(如 `order_items`、`account_configs`),同库单复数风格统一;库名与应用名一致。
- 【推荐】同一含义的列在各表中名称和类型一致(如都是 `user_id bigint`);不用无意义缩写。
- 【推荐】布尔语义列命名 `is_xxx` / `has_xxx`,不用 `deleted`、`if_deleted`、`flag`;时间点列用 `_at` 后缀,日期列用 `_date`。
- 【必须】索引命名:唯一索引 `uk_表名_字段…`,普通索引 `idx_表名_字段…`;PG 标识符上限 63 字节、MySQL 64 字符,超长被截断会重名,字段多时缩写字段名但保留完整表名。
- 【推荐】临时表、备份表用明确前后缀(如 `tmp_`、`_bak_20250101`),用完清理。

## 2. 建表与字段类型

### 通用

- 【必须】每张表有主键,默认列名 `id`;整型主键用 `bigint`,不用 `int`。
- 【必须】每张表有 `created_at`、`updated_at`,`NOT NULL` 带默认值;`updated_at` 随每次 UPDATE 更新(MySQL 用 `ON UPDATE`,PG 用触发器或 UPDATE 时显式 `SET updated_at = now()`)。
- 【必须】表和除 `id` 外的所有列写注释;枚举/状态列在注释中列出每个取值含义;改列含义或加枚举值时同步改注释。
- 【推荐】列默认 `NOT NULL` 并给合理默认值,仅当"未知"有业务意义时允许 NULL。
- 【必须】金额等精确小数用 `decimal(p,s)` / `numeric(p,s)`;【禁止】`float`/`double`/`real` 存金额;【禁止】PG `money` 类型。
- 【推荐】状态/类型列用 `smallint`(MySQL 可 `tinyint`),不用原生 `ENUM`(增删取值要改表)。
- 【禁止】用字符串存时间点;时间统一按 UTC 写入(纯日期分区键等例外需在注释写明格式)。
- 【推荐】长文本、大 JSON 与高频查询的窄字段分表,通过主键关联;【禁止】在库中存图片/文件,只存地址。
- 【推荐】允许适度冗余以减少 JOIN,冗余字段应低频修改、非超长文本。
- 【推荐】需要可追溯时用逻辑删除(`is_deleted` 或 `deleted_at`),唯一索引需纳入删除标记或改用部分索引;业务账号尽量不授予物理删除权限。
- 【推荐】不使用外键与级联(`ON DELETE CASCADE`),引用完整性由应用层保证;已有外键的,外键列必须有索引。
- 【推荐】建表时一次给足类型与长度,事后改类型多数要重写表或锁表;单表列数控制在 50 以内。

### MySQL

- 【必须】引擎 `InnoDB`,字符集 `utf8mb4`;【禁止】`utf8`/`utf8mb3`(存不了 emoji 等 4 字节字符);排序规则与库一致。
- 【必须】主键 `id BIGINT UNSIGNED NOT NULL AUTO_INCREMENT PRIMARY KEY`;【禁止】随机 UUID 字符串作聚簇主键(页分裂),需要时另建唯一列或用有序 UUID 存 `BINARY(16)`。
- 【必须】`created_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP`,`updated_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP`,需毫秒用 `DATETIME(3)`;【推荐】不用 `TIMESTAMP`(2038 上限、受会话时区影响)。
- 【必须】字符串用 `varchar(n)` 并给足长度(定长编码按精确长度,短文本 50、一般 255);超过约 5000 字符改 `text` 并考虑分表。
- 【推荐】无负数整型加 `UNSIGNED`;布尔用 `tinyint`(1=是,0=否);JSON 用 `JSON` 类型,按内部字段查询时建生成列加索引。
- 【必须】列注释用 `COMMENT '...'`,表注释用 `COMMENT='...'`。

### PostgreSQL

- 【必须】自增主键用 `id BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY`(允许显式插入)或 `GENERATED ALWAYS AS IDENTITY`;【禁止】`serial`/`bigserial`。UUID 主键用原生 `uuid` 类型,不用 `text`。
- 【必须】时间点用 `timestamptz`(`created_at TIMESTAMPTZ NOT NULL DEFAULT now()`);【禁止】无时区 `timestamp` 存时间点;【禁止】`timetz`、`CURRENT_TIME`。
- 【推荐】字符串用 `text`,需要上限时加 `CHECK (length(col) <= n)` 或用 `varchar(n)`;【禁止】`char(n)`。
- 【推荐】布尔用 `boolean`(与既有表风格一致时可用 `smallint`);JSON 用 `jsonb` 而非 `json`,常用查询属性拆成普通列。
- 【必须】注释用 `COMMENT ON TABLE` / `COMMENT ON COLUMN t.c IS '...'`。
- 【推荐】对象放在明确的 schema 中,必要时用 `schema.table` 限定,不依赖 `search_path`;取值约束用 `CHECK` 表达。

## 3. 索引

- 【推荐】除主键外按实际查询条件建索引;【禁止】在没有对应查询的列上建索引。
- 【必须】业务唯一的字段或组合建唯一索引,不能只靠应用层校验。
- 【必须】JOIN 关联列在被关联表上有索引,且两侧类型、字符集、排序规则完全一致(否则隐式转换使索引失效)。
- 【必须】组合索引遵循最左前缀:等值列在前、范围列在后,区分度高的靠左;`ORDER BY` 列紧接等值列可免排序;范围条件之后的列无法用于排序。
- 【禁止】冗余索引:已有 `(a, b)` 不再建 `(a)`;仅列顺序不同的组合索引需评估必要性。
- 【推荐】单索引列数 ≤ 4,单表索引数 ≤ 5–8;写多读少的表更要少建。
- 【推荐】状态/类型/布尔等低区分度列不单独建索引,放组合索引靠后;PG 可用部分索引(`WHERE status = 1`);【禁止】对其建 Hash 索引。
- 【推荐】利用覆盖索引避免回表(PG 可用 `INCLUDE (...)`)。
- 【禁止】MySQL 对 `text`/`blob` 整列建索引;长 `varchar` 用前缀索引 `col(20)`。
- 【推荐】PG 按函数查询建表达式索引(如 `lower(email)`);`jsonb` 包含查询用 GIN;超大且按时间追加的表可用 BRIN;GiST 等仅用于地理、范围等特殊场景。
- 索引失效常见原因(生成 SQL 时避免):隐式类型转换(`varchar` 列与数字比较)、索引列套函数或运算(`DATE(created_at) = ...`)、前导通配 `LIKE '%x'`、`<>`/`NOT IN`、`OR` 连接不同列、违反最左前缀、条件过宽。
- 【推荐】给优化建议时附 `EXPLAIN`;PG `EXPLAIN ANALYZE` 会真正执行语句,用于写语句时须包在事务中并回滚。

## 4. SQL 编写

### 查询

- 【禁止】`SELECT *`(交互式探查与 `EXISTS` 子查询除外),显式列出所需列。
- 【必须】多表查询中每列都用表名或别名限定。
- 【必须】计数用 `COUNT(*)`,去重计数用 `COUNT(DISTINCT col)`;注意 `SUM` 全为 NULL 时返回 NULL,需要时用 `COALESCE(SUM(col), 0)`。
- 【必须】判空用 `IS NULL` / `IS NOT NULL`,【禁止】`= NULL`;PG 中 NULL 安全比较用 `IS [NOT] DISTINCT FROM`。
- 【禁止】对可能含 NULL 的子查询用 `NOT IN (SELECT ...)`(结果会为空),改用 `NOT EXISTS`。
- 【必须】条件中常量类型与列类型一致(字符串列用字符串字面量)。
- 【推荐】时间范围用左闭右开 `col >= :start AND col < :end`,不对列套 `DATE()` 等函数。
- 【禁止】大表在线查询用 `LIKE '%x'` / `'%x%'`;确需模糊检索用全文索引(MySQL FULLTEXT、PG `pg_trgm`/`tsvector`)或搜索引擎。
- 【推荐】`IN (...)` 元素控制在数百以内,更多时改为 JOIN 临时表/`VALUES` 或分批;单值用 `=`。
- 【推荐】`OR` 跨不同列考虑改写 `UNION ALL`;无需去重时用 `UNION ALL` 而非 `UNION`。
- 【推荐】`ORDER BY` 需能确定唯一顺序(末尾追加主键),否则分页会重复或丢行。
- 【推荐】`GROUP BY` 查询的 SELECT 列只能是分组列或聚合表达式(符合 `ONLY_FULL_GROUP_BY`)。
- 【禁止】大表 `ORDER BY RAND()` / `random()`。

### 分页

- 【必须】面向用户的列表查询必须带 `LIMIT`;导出等大结果集分批读取。
- 【推荐】深分页改用书签分页:`WHERE id < :last_id ORDER BY id DESC LIMIT n`,多列排序时用 `(created_at, id)` 组合条件;无法改写时用"先查主键再回表"的延迟关联。
- 【推荐】总数统计与列表分开查询;大表避免每次精确 `COUNT(*)`。

### JOIN 与子查询

- 【推荐】单条 SQL 参与 JOIN 的表不超过 3 张,超过时考虑拆分查询或冗余字段。
- 【必须】JOIN 写明 `ON` 条件,【禁止】无意产生笛卡尔积。
- 【必须】`LEFT JOIN` 右表的过滤条件写在 `ON` 中,写在 `WHERE` 会退化为内连接。
- 【推荐】"是否存在"用 `EXISTS`,不用 `COUNT(*) > 0`;大表上的关联子查询改写为 JOIN;复杂查询用 CTE(`WITH`)提升可读性。

### 批量写入

- 【必须】`INSERT` 显式列出列名,不依赖列顺序。
- 【推荐】批量插入用多值 `INSERT ... VALUES (...), (...)`,每批 500–1000 行;PG 大批量导入用 `COPY`。
- 【推荐】幂等写入用 upsert:PG/SQLite `ON CONFLICT (cols) DO UPDATE/NOTHING`,MySQL `ON DUPLICATE KEY UPDATE`;【推荐】MySQL 不用 `REPLACE INTO`(先删后插,主键会变)。
- 【推荐】需要写入结果时 PG/SQLite 用 `RETURNING`,避免再查一次。

## 5. 写操作安全

- 【必须】`UPDATE` / `DELETE` 必须带能精确限定目标行的 `WHERE`;【禁止】无条件或恒真条件(`WHERE 1=1`)的全表修改。
- 【必须】执行 `UPDATE` / `DELETE` 前,先给出相同条件的 `SELECT COUNT(*)`(必要时含明细)确认影响行数,符合预期再执行。
- 【必须】大批量修改/删除(超过约 1 万行)分批执行:按主键区间或 `LIMIT` 每批 1000–5000 行,每批单独提交;PG 的 `UPDATE/DELETE` 无 `LIMIT`,用 `WHERE id IN (SELECT id ... LIMIT n)` 或主键区间。
- 【推荐】重要数据修改前备份受影响行(`CREATE TABLE t_bak_日期 AS SELECT ...`),并给出回滚语句。
- 【推荐】手工修数据在显式事务中进行:`BEGIN` → 执行 → 核对影响行数 → `COMMIT` 或 `ROLLBACK`。
- 【禁止】在 `UPDATE ... SET` 中用 `AND` 连接多个赋值(MySQL 会当布尔表达式静默执行),用逗号分隔。
- 【推荐】清空整表用 `TRUNCATE`(比无条件 `DELETE` 快),但它会重置自增、MySQL 中无法回滚,只用于运维清理,不写进业务代码。
- 【必须】删表、删列前确认无代码引用;删表先 `RENAME` 观察一段时间,确认无影响再 `DROP`;【禁止】直接 `DROP TABLE` / `DROP DATABASE` 线上对象。
- 【禁止】业务代码中执行 `DROP`、`TRUNCATE`、`GRANT` 等语句。

## 6. DDL 与结构变更

- 【必须】变更写成可重复执行的脚本:建表/建索引用 `IF NOT EXISTS`,删除用 `IF EXISTS`。
- 【推荐】DDL 与 DML 不放在同一事务或同一批脚本中(初始化数据除外);MySQL 的 DDL 会隐式提交当前事务。
- 【必须】调整索引先建新索引、确认生效后再删旧索引,【禁止】先删后建(窗口期退化为全表扫描)。
- 【必须】改列名、改类型、删列采用"扩展—迁移—收缩":加新列并双写 → 回填 → 切换读取 → 最后删旧列。
- 【推荐】新列加在末尾,允许 NULL 或带常量默认值,避免重写表;大表变更放在低峰期。

### PostgreSQL

- 【必须】线上表建/删索引用 `CREATE INDEX CONCURRENTLY` / `DROP INDEX CONCURRENTLY`,不能放在事务块内,须单独执行。
- 【必须】`CONCURRENTLY` 失败会残留 `INVALID` 索引,先删除再重建;依赖该索引的语句(如 `ADD CONSTRAINT ... USING INDEX`)须在它成功后单独执行,不与建索引放在同一批语句中。
- 【推荐】DDL 前设置 `SET lock_timeout = '3s'`,拿不到锁即失败重试,避免排队的 DDL 阻塞后续所有读写。
- 【推荐】加约束分两步:`ADD CONSTRAINT ... NOT VALID` 后再 `VALIDATE CONSTRAINT`(不阻塞读写);加 `NOT NULL` 先建并验证 `CHECK (col IS NOT NULL) NOT VALID`,再 `SET NOT NULL`(PG 12+ 免全表扫描)。
- 【推荐】PG 11+ 加常量默认值的列不重写表;易变默认值(如 `random()`)和多数改类型操作会重写表并持排他锁。
- 【推荐】大批量数据变更后执行 `ANALYZE 表名`。

### MySQL

- 【推荐】`ALTER TABLE` 显式写 `ALGORITHM=INSTANT` 或 `ALGORITHM=INPLACE, LOCK=NONE`,不满足时直接报错,避免退化为锁表的 `COPY`。
- 【推荐】8.0 中加列、改默认值通常可 `INSTANT`,加二级索引可 `INPLACE, LOCK=NONE`;改列类型、字符集、主键一般要重建表。
- 【必须】Online DDL 仍需短暂获取元数据锁(MDL):执行前确认该表无长事务或长查询,否则 DDL 及其后所有请求都会被阻塞。
- 【推荐】大表变更用 `gh-ost` / `pt-online-schema-change`;同一表的多个变更合并为一条 `ALTER TABLE`。

## 7. 事务与锁

- 【必须】事务尽量短:事务内不做 RPC、文件 I/O、等待用户输入;【禁止】长时间空闲在事务中(PG `idle in transaction`)。
- 【推荐】避免长事务:持锁久,PG 下阻止死元组回收导致表膨胀,MySQL 下 undo 膨胀。
- 【推荐】把占锁多、更新热点行的语句放在事务靠后位置,缩短持锁时间。
- 【推荐】多个事务按相同顺序(如主键升序)更新行以降低死锁;应用层对死锁/序列化失败做有限次重试。
- 【推荐】`SELECT ... FOR UPDATE` 的条件必须走索引(MySQL 无索引会锁大量行);队列消费用 `FOR UPDATE SKIP LOCKED`。
- 【推荐】注意默认隔离级别:MySQL InnoDB 为 `REPEATABLE READ`(有间隙锁),PG 为 `READ COMMITTED`。
- 【推荐】计数类更新用原子语句 `SET n = n + 1`,或用版本号乐观锁 `WHERE id = ? AND version = ?`,避免先查后改丢失更新。

## 8. SQLite 要点

- 【必须】外键默认不生效,需要时每个连接执行 `PRAGMA foreign_keys = ON`(不持久化)。
- 【推荐】并发读写开启 `PRAGMA journal_mode = WAL`(持久化在文件中)并设置 `busy_timeout`,避免 `database is locked`;网络文件系统不要用 WAL。
- 【推荐】列类型只是"亲和性",不强制;需要严格类型时(3.37+)建表加 `STRICT`。
- 【必须】自增主键写 `id INTEGER PRIMARY KEY`(必须是 `INTEGER` 而非 `INT`,才是 rowid 别名);只有不允许复用已删 ID 时才加 `AUTOINCREMENT`。
- 【推荐】无原生日期与布尔类型:时间全库统一存 ISO-8601 UTC 文本或 Unix 时间戳整数,布尔存 0/1。
- 【必须】`ALTER TABLE` 能力有限:仅支持改表名、`RENAME COLUMN`(3.25+)、`ADD COLUMN`、`DROP COLUMN`(3.35+,有限制);其他变更用"建新表—拷数据—删旧表—改名",在一个事务中完成。
- 【推荐】大量写入包在一个事务中(否则每条单独落盘,慢几个数量级);同一时刻只有一个写者,避免长写事务。
- 【推荐】不支持 `COMMENT`,说明写在脚本注释中;大小写不敏感比较用 `COLLATE NOCASE`。
- 【推荐】大量删除后可 `VACUUM` 回收空间(重写整个文件并锁库,勿在高峰执行)。

## 9. Redis 要点

- 【必须】key 用冒号分层:`业务:对象:ID[:字段]`(如 `app:user:10086:profile`);只用可打印 ASCII,不含空格换行,简短可读(建议 ≤ 128 字节)。
- 【必须】除明确需要常驻的数据外,所有 key 都设过期时间,并用 `SET k v EX 秒` 一步完成;同批写入的 key 给过期时间加随机偏移,避免集中失效(雪崩)。
- 【禁止】线上执行 `KEYS`、`FLUSHALL`、`FLUSHDB`、`CONFIG SET`、`DEBUG`、`SHUTDOWN` 等阻塞或高危命令;遍历 key 用 `SCAN` + `MATCH` + `COUNT` 分批。
- 【禁止】对大集合直接 `HGETALL`、`SMEMBERS`、`LRANGE 0 -1`、`ZRANGE 0 -1`;改用 `HSCAN`/`SSCAN`/`ZSCAN` 或分段读取。
- 【推荐】避免大 key:string 值 ≤ 10KB,hash/list/set/zset 元素 ≤ 5000;超出按 ID 取模等方式拆分。
- 【必须】删除大 key 用 `UNLINK`(4.0+ 异步释放)或先分批缩减再删,【禁止】直接 `DEL` 大 key;按模式批量删除用 `SCAN` + `UNLINK`。
- 【推荐】热点 key 用本地缓存、读副本或拆成多个副本 key 分散压力;防穿透可缓存空值(短过期)或用布隆过滤器。
- 【推荐】批量读写用 `MGET`/`MSET`/pipeline,单批数百以内;集群模式多 key 命令要求同槽位,必要时用 hash tag `{...}`。
- 【推荐】多步原子操作用 Lua 或 `MULTI`/`EXEC`,脚本保持简短;分布式锁用 `SET key token NX PX 毫秒`,释放时用 Lua 校验 token 再删除。
- 【推荐】按数据形态选结构:对象用 hash,计数用 `INCR`,排行用 zset,去重用 set/HyperLogLog;不把 Redis 当作唯一持久化存储。

## 10. 示例(生成时参照其写法)

MySQL 建表:

```sql
CREATE TABLE IF NOT EXISTS orders (
  id          BIGINT UNSIGNED NOT NULL AUTO_INCREMENT PRIMARY KEY,
  order_no    VARCHAR(32)     NOT NULL COMMENT '订单号',
  user_id     BIGINT UNSIGNED NOT NULL COMMENT '下单用户 ID',
  status      TINYINT         NOT NULL DEFAULT 0 COMMENT '状态:0 待支付,1 已支付,2 已取消',
  amount      DECIMAL(12,2)   NOT NULL DEFAULT 0 COMMENT '订单金额(元)',
  paid_at     DATETIME        NULL COMMENT '支付时间(UTC),未支付为 NULL',
  is_deleted  TINYINT         NOT NULL DEFAULT 0 COMMENT '是否删除:0 否,1 是',
  created_at  DATETIME        NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间(UTC)',
  updated_at  DATETIME        NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP COMMENT '更新时间(UTC)',
  UNIQUE KEY uk_orders_order_no (order_no),
  KEY idx_orders_user_id_created_at (user_id, created_at)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_0900_ai_ci COMMENT='订单';
```

PostgreSQL 建表:

```sql
CREATE TABLE IF NOT EXISTS orders (
  id          BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
  order_no    TEXT          NOT NULL CHECK (length(order_no) <= 32),
  user_id     BIGINT        NOT NULL,
  status      SMALLINT      NOT NULL DEFAULT 0 CHECK (status IN (0, 1, 2)),
  amount      NUMERIC(12,2) NOT NULL DEFAULT 0,
  paid_at     TIMESTAMPTZ,
  is_deleted  BOOLEAN       NOT NULL DEFAULT false,
  created_at  TIMESTAMPTZ   NOT NULL DEFAULT now(),
  updated_at  TIMESTAMPTZ   NOT NULL DEFAULT now()
);
CREATE UNIQUE INDEX IF NOT EXISTS uk_orders_order_no ON orders (order_no);
CREATE INDEX IF NOT EXISTS idx_orders_user_id_created_at ON orders (user_id, created_at);
COMMENT ON TABLE orders IS '订单';
COMMENT ON COLUMN orders.status IS '状态:0 待支付,1 已支付,2 已取消';
COMMENT ON COLUMN orders.amount IS '订单金额(元)';
COMMENT ON COLUMN orders.paid_at IS '支付时间,未支付为 NULL';
```

SQLite 建表:

```sql
CREATE TABLE IF NOT EXISTS orders (
  id          INTEGER PRIMARY KEY,
```

书签分页(下一页,上一页最后一条为 :last_created_at / :last_id):

```sql
SELECT o.id, o.order_no, o.amount, o.created_at
FROM orders o
WHERE o.user_id = :user_id
  AND (o.created_at, o.id) < (:last_created_at, :last_id)
ORDER BY o.created_at DESC, o.id DESC
LIMIT 20;
```

安全修改数据(先确认影响行数,再在事务内执行并核对):

```sql
SELECT COUNT(*) FROM orders WHERE status = 0 AND created_at < '2025-01-01';
BEGIN;
UPDATE orders SET status = 2, updated_at = now()  -- MySQL 写 CURRENT_TIMESTAMP 或省略
WHERE status = 0 AND created_at < '2025-01-01';
-- 影响行数与上面一致则 COMMIT,否则 ROLLBACK
COMMIT;
```

分批删除大量数据(每批单独提交,重复执行直到影响行数为 0):

```sql
-- MySQL
DELETE FROM operation_logs WHERE created_at < '2025-01-01' ORDER BY id LIMIT 2000;
-- PostgreSQL
DELETE FROM operation_logs
WHERE id IN (SELECT id FROM operation_logs WHERE created_at < '2025-01-01' ORDER BY id LIMIT 2000);
```

在线变更:

```sql
-- PostgreSQL:不阻塞读写地建索引、加约束(每条单独执行,不放在事务块里)
SET lock_timeout = '3s';
CREATE INDEX CONCURRENTLY IF NOT EXISTS idx_orders_paid_at ON orders (paid_at);
ALTER TABLE orders ADD CONSTRAINT ck_orders_amount_non_negative CHECK (amount >= 0) NOT VALID;
ALTER TABLE orders VALIDATE CONSTRAINT ck_orders_amount_non_negative;

ALTER TABLE orders ADD COLUMN remark VARCHAR(255) NOT NULL DEFAULT '' COMMENT '备注', ALGORITHM=INSTANT;
ALTER TABLE orders ADD INDEX idx_orders_status_created_at (status, created_at), ALGORITHM=INPLACE, LOCK=NONE;
```

Redis:

```text
SET app:order:10086:detail '{"status":1}' EX 3600        # 写入即带过期时间
```
